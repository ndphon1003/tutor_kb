# Architecture Decision Records

This directory stores Architecture Decision Records (ADRs) for accepted, cross-cutting decisions that need durable context and rationale.

## Current state

No ADRs are recorded yet.

## When to add an ADR

Create an ADR when a decision:

- Affects multiple components or repositories
- Establishes a lasting technical or architectural constraint
- Has meaningful alternatives or trade-offs
- Is costly to reverse
- Needs rationale beyond a short convention

Jira is planned as the future source for product requirements and task tracking, but is not configured yet. Detailed implementation remains in source repositories.

## File naming

The naming and numbering convention is **TBD**. Until it is decided, do not create placeholder decisions.

## Suggested ADR content

Use this structure after the ADR convention is approved:

```markdown
# <Decision title>

## Status

Proposed | Accepted | Superseded

## Context

What problem requires a decision?

## Decision

What was decided?

## Consequences

What are the positive, negative, and operational effects?

## Alternatives considered

What other options were evaluated?
```

The template is guidance only; ADR lifecycle, identifiers, and approval ownership are **TBD**.
